Catching Attacks in Named Data Networking

One unsupervised Isolation Forest, trained only on clean traffic, that detects two different NDN attacks on emulated and simulated networks.

Ankit Pokhrel
2 min read·2026·source

The problem

Named Data Networking fetches content by name instead of talking to a host. Routers cache data and keep state for every pending request, which opens two attacks: Interest Flooding, which floods routers with requests for content that doesn't exist, and Cache Pollution, which fills caches with junk. No single threshold rule catches both. We wanted one detector that does, trained without ever seeing an attack.

What we did

One Isolation Forest, trained only on clean traffic, tested on two independent platforms across the same three topologies (tree, dumbbell and a DFN-style mesh): miniNDN, which emulates the network with the real NDN forwarding daemon, and ndnSIM, an ns-3 simulator. On ndnSIM we swept the attacker's rate across 297 runs to find the slowest attack each one can still be caught at. KS hypothesis tests and feature-ablation studies showed which features actually carry each attack.

The textbook signature wasn't there

The standard story says Interest Flooding blows up a router's Pending Interest Table. In our emulation it didn't: PIT size was statistically the same under attack: the forwarder rejects attack requests with NACKs, and the table drains between polls. The signal was in the NACK rate and the satisfaction ratio instead, which corrects the usual picture of this attack.

The hard part: a model that learned failure was normal

Early on the detector caught almost nothing. The model wasn't the problem. 22.6% of our "normal" training samples were idle intervals that the logging code recorded as total failure, so the model learned that failure looks normal. With clean data the same model found the attacker 89-98% of the time.

A second fix made it robust to load. Absolute rate features flagged busy but healthy traffic as attacks, so we replaced them with ratios.

The result: the detection floor

At a realistic false-positive rate of about 2%, Cache Pollution stays detectable down to about 44 Interests per second per attacker, while Interest Flooding stays detectable down to about 1.8. The floors hold across all three topologies, including ones the model never trained on. Cache Pollution is volumetric, so it has to shout to be seen; Interest Flooding looks different, not just louder.

So the practical limit of anomaly detection here isn't peak accuracy at one attack rate. It's the floor: how quietly an attacker can operate before the detector loses them. The paper is under revision for a journal.
